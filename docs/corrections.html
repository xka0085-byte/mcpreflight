Corrections log

mcpreflight MCP endpoint scanner. Last updated 2026-11-01.

When an external user tells us a scan result is wrong, we re-run the case, fix the scanner, and record it here. This page lists every correction we have made to published results, with the evidence link and the affected numbers. We publish these because a scanner that hides its errors cannot be trusted on its successes.

Effect on the published numbers

This is the part of the log that has to be read carefully. Two censuses have archived raw output. The first, 2026-10-19, is the truncated one, kept here for provenance:

  • 9,991 endpoints scanned, which we now know is the first 300 pages of registry order, not the registry (see the 2026-10-31 entry)
  • 4,751 passed the MCP handshake and schema check, 47.6%
  • 3,182 auth-gated
  • 2,001 unknown or unreachable
  • 57 failed

The second is the complete traversal of 2026-11-01, and it is the run the site now quotes:

  • 198,345 registry entries across 1,984 cursor pages, complete traversal
  • 52,765 latest-version active servers, of which 35,327 carry a remote HTTP transport
  • 20,908 passed the MCP handshake and schema check, 59.2%
  • 10,032 auth-gated
  • 4,232 unknown or unreachable
  • 155 failed, 0.4%

A re-run on 2026-10-21 produced a different count. That output was never committed, so we cannot recompute it, and we have stopped quoting it; it no longer appears anywhere on this site. If we re-run again, the raw JSON goes into the repository first and onto the page second.

For the same reason the 48.8% pass rate and the 4,879 / 5,069 / 43 breakdown published up to 2026-10-29 are withdrawn: no archived output backs them. The site now quotes three measurements and never mixes them. One is the 2026-11-01 complete census, the current default. The second is the 2026-10-19 truncated census above, kept only so an older citation can be traced. The third is a probabilistic sample taken on 2026-10-29 from the 34,190 active remote servers in the registry, 500 endpoints drawn: 316 passed (63.2%, 95% CI 58.9-67.3), 123 auth-gated, 58 unknown or timed out, 3 failed. The endpoint list and raw responses are at mcpreflight-audit.pages.dev/audit.

Every number above is our own output. None has been independently recomputed by a third party. Where a figure is quoted elsewhere it should carry its date and the words "mcpreflight scan", and it should be one of the three measurements named here — the complete 35,327 census of 2026-11-01, the truncated 4,751 census of 2026-10-19, or the 63.2% sample.

External reviews

Two external reviews are on record.

  • Novence-ai/mcp #4: the maintainer reported that anonymous handshakes worked over streamable HTTP with a session header. Our re-test confirmed it and led to the first four corrections above.
  • szaffarano/org-mcp-server #232: the maintainer asked us to re-test a tools/list schema report on v0.1.2, then shipped v0.1.3. Our re-test confirmed the missing fields were present, and the maintainer confirmed and closed the issue.
These two threads are the only cases where someone outside this project checked our claim and acted on it. That is useful evidence that a report changed a product. It is not evidence of commercial demand.

How to reproduce

Every result on this site can be re-run. The scanner is open source (bin/mcpreflight.mjs), and node test/smoke.mjs runs the conformance cases that regressions in 0.5.0 broke: stateful Mcp-Session-Id headers, JSON and SSE responses, unauthenticated 401, 308 redirects, one retry on 429, and malformed tool schemas. It is a plain Node script against a local fixture server — no network, no credentials. The published npm package is still 0.5.0 and predates these fixes; the fixed scanner is in the repository and ships with the next release.
