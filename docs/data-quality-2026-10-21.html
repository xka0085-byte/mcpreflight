MCP census data quality note

2026-10-21. This note records a measurement defect in our MCP endpoint census, what changed after the fix, and what remains unverified.

What happened

A maintainer told us on 2026-10-20 that an endpoint we reported as NO_RESPONSE actually completed an anonymous handshake. We re-tested it: HTTP 200, an Mcp-Session-Id header, and an SSE event carrying the initialize result. The report was wrong.

Root cause: our scanner did not echo the session header on tools/list. Stateful Streamable HTTP servers answered 400, and we recorded that as a dead endpoint. Four more defects surfaced while repairing it: redirects were not followed, any 401 without a Bearer challenge was not counted as gated, 429 and 5xx were not retried, and the body cap was too small.

Deprecated: the old anonymous handshake pass rate of 48.8 percent must not be quoted. Under the corrected scanner the same census gives 51.2 percent PASS, 35.2 percent AUTH_GATED, 13.2 percent UNKNOWN, 0.4 percent FAIL. Both numbers use the same endpoint list and the same read-only method.

What this does and does not prove

  • It proves that at least 369 endpoints were previously misclassified. A random sample of 60 old NO_RESPONSE endpoints gave 19 PASS and 12 AUTH_GATED after the fix.
  • It does not prove the new number is correct. No independent party has recomputed it yet, and this re-scan ran from one network location.
  • Classification is still the scanner's own judgment. AUTH_GATED means the endpoint answered 401 or 403 anonymously. PASS means the schema checks passed. Neither is a security or quality certification.

Reproduce it

Run node bin/mcpreflight.mjs schema <url> --format=json against any endpoint. The raw per-server records behind this note are in trust-data/scan-full.jsonl. The pre-fix records are kept in trust-data/scan-full.pre-fix-2026-10-21.jsonl.

If you find a disagreement, open an issue with the endpoint and the exact request. We will publish the correction here.
