x402 payments in the MCP Registry: a 1,583-endpoint census

Every endpoint in the MCP Registry that advertises x402 or HTTP-402 payments, probed read-only and re-probed weekly. This is a dataset, not a product page: the numbers below are measured, the files are downloadable, and the definition of the cohort is fixed so the series stays comparable. No API key, no wallet, no signature, no settlement.

Endpoints that advertise payments complete an anonymous handshake 7.0 pp more often than the registry as a whole, and sit behind an auth gate 27.1 pp less often. Both follow from the same mechanical reason: an endpoint that wants an agent to pay it has to stay callable by an agent that has not been given a key yet.

1,039 of 1,583 endpoints answer with a tool list, publishing 23,360 tools in total.

The other side of that gap is visibility, not quality: 32.0% of the cohort gave no anonymous response at all, against 12.0% registry-wide. Addresses that were published recently, or that answer only on a paid path, have not been smoke-tested by anyone yet — which is exactly the population a preflight run is for.

Counts are finding occurrences, not endpoints: a schema code such as PROPERTY_DESCRIPTION_MISSING fires once per undocumented tool property, so its total legitimately exceeds the cohort size, while NO_RESPONSE matches the UNKNOWN endpoint count one for one. Codes are the raw findings from the same read-only probe, uncollapsed, so a reader can re-derive them from x402-summary.json (findingCodes) instead of trusting this table; the per-endpoint code list is in the cohort CSV.

Definition, so the number can be checked

A registry entry joins the cohort when its title, description or URL matches x402 or http-402 case-insensitively. The rule was fixed on 2026-10-15 and is not tuned per sweep. Each endpoint is probed read-only: one anonymous initialize plus tools/list for the handshake status, and the HTTP response for the 402 challenge shape. PASS means a clean anonymous handshake; AUTH_GATED means a confirmed intentional gate (401 with WWW-Authenticate, or live RFC 9728 resource metadata); UNKNOWN means no anonymous response at all; FAIL means a response that arrived but broke the handshake.

PASS is a reachability and shape measurement. It is not a security audit, a payment-success guarantee, or a claim that the endpoint is worth paying.

Read the series with the cohort change in mind

The cohort was 293 endpoints until 2026-10-30. From 2026-11-01 the filter was widened to the full registry and the cohort became 1,583, which is roughly the whole addressable population rather than a named subset. The clean-handshake share moves from the mid-70s to the mid-60s at that boundary because a larger, less curated sample entered — a composition change, not a quality collapse. Only rows with the same cohort size are strictly comparable, which is why both columns are published side by side.

How this differs from other x402 counts

Other published x402 ecosystem numbers measure a different thing on a different sample: whether a seller can be listed or discovered. This dataset measures whether an endpoint completes an anonymous MCP handshake. A listing rate and a handshake rate are not interchangeable, and neither is a refutation of the other. Where a number here disagrees with a number elsewhere, the first thing to compare is the denominator and the operation being counted, not the percentage.

Download and cite

The files are plain CSV and JSON, MIT licensed, refreshed on the same weekly cadence as the series:

  • x402-cohort-latest.csv — one row per endpoint: name, url, status, protocol version, tool count, finding codes, checked at.
  • x402-history.csv — the weekly series used for the table above.
  • x402-summary.json — definitions, counts, distributions and the citation string, so a downstream tool does not have to scrape this page.
