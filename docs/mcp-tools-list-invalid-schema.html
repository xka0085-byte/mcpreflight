My tools/list fails JSON Schema validation

In the 2026-11-02 sweep, 146 endpoints returned a tools/list that fails deterministic validation (0.4% of 35,327), plus smaller clusters with the same root cause: 7 endpoints declare required properties that are never defined, 6 have malformed property definitions, and 3 return an inputSchema that is not an object at all.

How common it is

  • Endpoints whose tools/list fails validation — 146 of 35,327 (0.4%)
  • Endpoints with required properties missing from the schema — 7
  • Endpoints with an inputSchema that is not an object — 3
  • Endpoints with malformed property definitions — 6

What it means

These are structural defects, not style notes: a client that validates before calling will reject the tool, and one that does not will fail at call time with a worse error. The two failure shapes worth checking first are inputSchema that arrives as something other than an object (often a schema wrapper leaking through), and required that names a key absent from properties — the latter usually comes from a hand-written schema that drifted from the implementation.

Check it in one command

npx @eidonze/mcpreflight schema https://your-server.example.com/mcp

The check is read-only. It performs the handshake steps and reports which one answered what; it does not authenticate, mutate, or write anything to the server.

Three steps

  1. Print the raw tools/list response rather than a typed view: the defect is in the bytes, and most SDK clients hide it by coercing.
  2. For each tool, assert that inputSchema.type === "object" and that every entry in required also exists in properties.
  3. Validate the full response against the MCP schema before release, in the same test that already calls tools/list — the check is cheap and catches the drift at the commit that introduces it.
