How healthy was the ecosystem at the October 2026 snapshot? We ran a read-only initialize + tools/list check against the 35,327 remote endpoints that sweep returned from the official MCP Registry: 20,908 (59.2%) completed a clean handshake, 14,264 (40.4%) gave no anonymous response, and 155 failed outright. Among responders we logged 233,012 property-level schema findings, and 82% negotiate the 2025-06-18 protocol revision. Every number is reproducible with one open-source command, and per-server reports live in the Trust Directory.

What we did

We swept the official MCP Registry for active servers with a remote (HTTP) transport and sent exactly two JSON-RPC requests to each endpoint our complete 2026-11-01 sweep returned, 35,327 of them: initialize and tools/list. We validated protocol negotiation and every tool's input/output JSON Schema. No tool was ever called, no authentication was attempted, no data beyond the handshake was read. The whole thing is open source and one command reproduces any single result:

npx @eidonze/mcpreflight schema <endpoint-url>

Findings

1. Four in ten endpoints our sweep returned are not usable anonymously. 14,264 of 35,327 remote endpoints (40.4%) did not complete a clean initialize + tools/list handshake. This bucket mixes genuinely broken servers, temporarily down ones, and endpoints that require auth by design — an anonymous check cannot distinguish them, which is itself part of the story: an agent consuming the registry today cannot tell "requires OAuth" from "dead on arrival" without trying and failing.
2. Protocol adoption is fragmented, but the 2025-06-18 revision now dominates. Of the 20,953 servers that negotiated a protocol version, 82% run 2025-06-18 and 14% are still on 2025-03-26. Only 117 servers (0.6%) speak the newest revision (2026-07-28).

3. Schema hygiene is the quiet tax. Among servers that did respond, the dominant schema finding was missing description on input properties — 221,048 property-level findings across 8,521 servers. Tool descriptions are what an LLM reads to decide when and how to call a tool; missing ones measurably degrade agent tool selection. 132 servers returned a tools/list that fails JSON Schema validation outright, 110 returned an invalid initialize response.
4. The community index and the official registry disagree. We cross-checked the largest community awesome-list (4,536 GitHub repo links) against registry data: only 226 of its links correspond to servers we have registry scan coverage for, and 84 of those do not pass a clean anonymous handshake. Discovery is fragmented across at least two inconsistent indexes.
5. A third-party proxy sits inside the official registry. 217 registry entries (0.6%) do not point at a maintainer's own server but at server.smithery.ai proxy URLs. All 217 refused an anonymous handshake — 0% completed initialize + tools/list, against a 40.0% no-handshake baseline across the other 35,110 endpoints. Most of that gap is by design: the proxy expects a per-server config and key. The consequence is the same either way: an agent, or any independent auditor, following the official registry cannot verify these 217 servers at all without first signing up with a third party — and cannot tell auth-by-design from dead-on-arrival, the same blindness we found across the sweep, here concentrated in one vendor's corner of the index. We started this comparison after a maintainer flagged auto-registered placeholder entries (kirbah/mcp-youtube#290); our data cannot confirm or refute what sits behind the proxy, only that it is unverifiable from the outside.
6. The x402 economy is already inside the registry — and healthier than average. 1,583 endpoints reference x402 / HTTP-402 payments in their registry metadata. They pass a clean anonymous handshake at 66.9% (1,059 of 1,583), against the 59.2% baseline of the same sweep; 520 remain unverifiable anonymously (19 AUTH_GATED, 501 UNKNOWN) and 4 fail outright. The gap has a mechanical explanation: a payment server whose challenge flow is malformed fails its first agent transaction, so this cohort ships cleaner handshakes. As agent-payment volume grows (Coinbase's x402 protocol crossed 138M reported transactions), this is the cohort where challenge-shape drift and misconfiguration will concentrate — 66.9% is today's baseline, and we now track challenge-shape drift on these endpoints as a dedicated check.

Limitations (read this before quoting us)

  • Anonymous handshake only. Servers behind OAuth are not broken — but the registry does not label them, so the 40.4% figure is an upper bound on breakage, not an exact count.
  • Static schema checks do not predict model tool selection and do not prove behavior across clients.
  • One point in time (2026-10-11), re-scanned weekly; per-server history and diffs are planned.
  • If your server is listed as "no handshake" and requires auth by design: that's expected — you can ignore it, or reply on the directory to be excluded.

What this scan does not cover

One limitation used to sit next to the headline number, and it is now fixed rather than explained. The 9,991 figure we published in October was what a scanner capped at 300 cursor pages returned; it was never the size of the registry. The cap was the constraint: a complete traversal walks 1,984 cursor pages and returns 198,345 registry entries, of which 52,765 are the latest version of an active server and 35,327 carry a remote HTTP transport. Those 35,327 are what this page reports, scanned in one pass rather than assembled from a partial cache. The public API still exposes no total, so any number has to come from a traversal; the difference now is that the script producing it is in the repository, so every figure here can be re-derived instead of trusted.

A second measurement sidesteps the question by sampling instead of sweeping: 500 endpoints drawn at random on 2026-10-29 from the then-current 34,190-endpoint census, of which 316 completed a clean anonymous handshake (63.2%, 95% CI 58.9-67.3). Method and raw responses: mcpreflight-audit.pages.dev. The two numbers are not interchangeable. The census describes the endpoints our sweep reached; the sample estimates the wider registry. Do not average them and do not quote one as the other.
