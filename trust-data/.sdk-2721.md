Same class of issue, observed from the client side: we run a read-only scanner (MCP `initialize` + `tools/list` only) over the ~10k endpoints registered in the official MCP Registry, and draft-07-only `outputSchema` is a recurring shape in the wild. It usually passes unnoticed because most clients tolerate draft-07 in practice — until one validates strictly, at which point it again looks like the client's bug.

For anyone debugging this on the server side: the published `$schema` (or its absence) is mechanically detectable before deploy, the same way missing `required` fields are. We gate that in CI with a read-only check (MIT: https://github.com/xka0085-byte/mcpreflight). If it helps the maintainers weigh #2677 vs this one: both stem from the same `toJsonSchemaCompat` target default, so a single fix path likely covers both.
