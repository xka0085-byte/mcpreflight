Since this template is positioned as production-ready, one suggestion for the release path: gate the deployed endpoint, not just the build.

We scan ~10k MCP endpoints registered in the official registry every week, and the most common production failure is not a crash — it's a deployed server whose `tools/list` schemas drifted from what the author tested (missing `required`, empty `inputSchema` after schema transforms, renamed params). Strict clients then fail in ways that look like their bug, not the server's.

A one-block CI step catches this on every release:

```yaml
- name: MCP preflight
  uses: xka0085-byte/mcpreflight@v1
  with:
    endpoint: ${{ vars.MCP_ENDPOINT }}
    mode: schema
```

Read-only by design: it sends only MCP `initialize` + `tools/list`, never calls tools. For OAuth-protected deployments where an anonymous handshake is expected to fail, set `fail-on: false` and treat it as an informational smoke check.

MIT, zero-dependency: https://github.com/xka0085-byte/mcpreflight — happy to send a PR against the template's example workflow if useful.
