Nice boilerplate — the Stripe-paid-tools example is exactly the pattern a lot of server authors copy.

One gap we kept hitting with this pattern: it deploys fine, but nothing checks the deployed endpoint itself. Two failure classes show up in the wild that neither local testing nor `wrangler deploy` catches:

1. The MCP handshake or tool schemas regress after a deploy or dependency bump — the registry entry and the live server drift apart, and clients break silently.
2. For paid tools, the payment-required response isn't shaped the way client SDKs expect (wrong status, missing `accepts[]`, payment document in the wrong place).

Both are cheap to gate in CI with a read-only check (no tool calls, no payment attempt):

```yaml
- name: Preflight deployed endpoint
  uses: xka0085-byte/mcpreflight@v1
  with:
    endpoint: ${{ vars.MCP_ENDPOINT }}
    mode: schema
```

and for the paid-tools example:

```yaml
- uses: xka0085-byte/mcpreflight@v1
  with:
    endpoint: ${{ vars.PAID_ENDPOINT }}
    mode: inspect
    fail-on: false   # informational preflight
```

It's MIT, zero-dependency, open source: https://github.com/xka0085-byte/mcpreflight — `schema` sends only MCP `initialize` + `tools/list`; `inspect` only reads the 402 challenge document. Happy to send a PR if you'd like it wired into the example workflow.
